The photo spot note

One note per spot, one entry per motif. The printed guide's double page, minus the parts a book cannot do and plus the parts it cannot: live sun times, a shooting-direction light relation, and a capture state per motif.

Neuchâtel (Neuenburg)

📷 Photo spot · Schweiz › Neuchâtel · ★★★★★ · zuletzt: 14.06.2025 · 1 von 2 Motiven fotografiert

Photo spots inside a trip

A photo spot is a place type, so it is already a valid itinerary stop. What the design adds is the three things that make that stop worth having: a sun band behind the day, a golden-hour prefill when you add the stop, and a warning when two spots want the same light.

Data model

photospot becomes the ninth entity type and the fifth member of TRAVEL_PLACE_TYPES. That single decision buys the whole existing place machinery: the Country/City hierarchy, geoLocation, visited/lastVisit, rating, the gallery, the dashboard sort, visit derivation, and validity as an itinerary stop target.

--- the note level, place shape shared with the other four kinds ---
type: photospot
country: "[[Switzerland]]"
city: "[[Neuchâtel]]"
geoLocation: ["46.9899", "6.9293"]   # the spot's anchor
rating: 5
visited: true
lastVisit: 2025-06-14

--- new, flat, because Obsidian's property editor renders scalars ---

The three decisions worth arguing about

DecisionWhat it buysWhat it costs
Ninth type, inside the place family One as const entry and one folder mapping, and photo spots are gallery-visible, dashboard-sortable, trip-linkable and health-checkable on day one. Photography fields stay where only photo spots pay for them. Nine folders instead of eight in the health check, and a docs sweep for every "eight" in the repo.
motifs: as a list, not mainMotif/secondaryMotif The printed page has exactly two motifs; real spots have one to five. A list does not cap the count and does not duplicate eleven sub-fields per slot. Obsidian's property editor will not render it, so motifs are edited in the block. The trip's stops: already made this trade.
captured per motif, separate from visited "Do I still owe myself this picture" is the question a photo spot exists to answer, and it comes apart from "have I been here" constantly. It is what lets the gallery say 1 of 2 captured. Two visit-shaped fields on one note, which needs one sentence of explanation in the docs and one in the UI.

Fixed vocabularies, translated but never localized in the note

Light window values stay English identifiers in the YAML, exactly as TRAVEL_STATUS_VALUES does. Only their labels are translated. A German vault that wrote goldene-stunde-abends into its notes would be unreadable by the same vault switched to English.

blue-hour-morning sunrise golden-hour-morning day overcast golden-hour-evening sunset blue-hour-evening night

Build order

Eight phases, each independently shippable, each leaving the plugin in a working state. Phase 0 alone already gives you photo spots as notes with zero new UI code.
